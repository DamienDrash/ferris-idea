# Keymap coverage against the open keymap

Generated by `scripts/keymap-coverage.py` (SPEC-0028 v4 behaviour 9); do not edit by hand.
`python3 -I scripts/keymap-coverage.py --check` fails when it is out of date.

**Reference:** the macOS keymap of the open keymap files of `JetBrains/intellij-community`
(Apache-2.0) at commit `d4018fb57c367e7b5d895bd8a0c84c382efd0e17`, bundled unchanged in `crates/ui/keymaps/`:
`Mac OS X 10.5+.xml` over `$default.xml`, inherited shortcuts with Control and Meta exchanged
(SPEC-0028 behaviours 3 and 3a). **IDECraft:** the bundled macOS keymap, which is these files plus
the shortcuts listed in `crates/ui/keymaps/macos-deviations.json`.

## What is measured, and what is not

- An action counts as present when its id is a string literal in the sources that carry out actions
  (`crates/workbench/src`, `crates/editor/src/commands.rs`, `crates/ui/src/tool_windows.rs`; test
  modules and comments left out), or when it is one of the mapped actions below. This is evidence
  from the source text, not from running the action: it says neither that the action does all the
  reference's action does, nor in which focus it works.
- **same** means every shortcut the reference keymap gives the action is bound in IDECraft's keymap;
  additional shortcuts of IDECraft are listed under the deviations. Mouse shortcuts and gestures are
  compared as keymap entries only.
- A chord an action yields to another action of IDECraft's keymap (`GotoTest` on the chord of
  `ReopenClosedTab`, SPEC-0071 v10) does not count as its shortcut: the action exists and the
  chord does not run it.
- The reference also binds keys in the declarations of its actions and plugins, outside the keymap
  files. Those are not part of this comparison, and nothing here was checked against a running
  reference IDE.
- Keys that popups, trees and dialogs handle themselves, without the keymap, are not measured.
